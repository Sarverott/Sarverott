```md
You can use YAML files in Astro using the built-in Content Collections file() loader or by installing a Vite YAML plugin.

Option 1: Content Collections Loader (Recommended)

Astro includes built-in support for YAML files inside content collections using file() from astro/loaders.
1. Configure your collection in src/content.config.ts:
typescript
import { defineCollection } from 'astro:content';
import { file } from 'astro/loaders';
import { z } from 'astro/zod';

const dataCollection = defineCollection({
  loader: file("src/data/my-data.yml"),
  schema: z.object({
    id: z.string(),
    // define your schema fields here
  }),
});

export const collections = { dataCollection };
Używaj kodu z rozwagą.

Option 2: Vite Plugin (@rollup/plugin-yaml)

To import .yml or .yaml files directly into your Astro components as JavaScript objects:
1. Install the plugin:
bash
npm install @rollup/plugin-yaml -D

2. Add it to your astro.config.mjs:
javascript
import { defineConfig } from 'astro/config';
import yaml from '@rollup/plugin-yaml';

export default defineConfig({
  vite: {
    plugins: [yaml()]
  }
});
Używaj kodu z rozwagą.

astro
```

```md
You can absolutely keep your YAML exactly **as-is** without converting it to a list.

In TypeScript and Zod (which Astro uses), this structure is handled as a **Record** (or a nested object). Zod makes it easy to handle optional fields like title and description, or even entire platforms that might be completely empty.

Here is how to set up your schema and read the data per label:

## **1\. Define the Schema (src/content.config.ts)**

Since your YAML file is an object where the keys are the platform names (labels) and the values are their parameters, use z.record() combined with z.object() and z.optional():

`import { defineCollection } from 'astro:content';`  
`import { file } from 'astro/loaders';`  
`import { z } from 'astro/zod';`

`const socialMediaCollection = defineCollection({`  
  `loader: file("src/data/socials.yml"),`  
  `schema: z.object({`  
    `// This expects an object mapping string keys (like 'instagram', 'x')`   
    `// to our custom link object structure`  
    `links: z.record(`  
      `z.string(),`  
      `z.object({`  
        `url: z.string().url().optional(),`  
        `title: z.string().optional(),`  
        `description: z.string().optional(),`  
      `}).nullable() // Allows platforms to exist but be empty/null (like youtube)`  
    `).optional()`  
  `}),`  
`});`

`export const collections = { socials: socialMediaCollection };`

*(Note: Depending on how your loader interprets the root of the file, you might need to wrap your YAML keys under a single parent key like links:, or use a custom ID structure if you are loading a collection of multiple files. If this is a single standalone file at the root, treating it as an object with dynamic keys works best).*

## **2\. Read the Data in your Astro Component**

To read it per label, you can use Object.entries() to loop through the keys and values. This gives you both the label (e.g., instagram) and all its parameters:

`---`  
`import { getEntry } from 'astro:content';`

`// Fetch the data from the collection`  
`const socialData = await getEntry('socials', 'socials'); // Adjust IDs based on your file name`  
`const links = socialData?.data || {};`  
`---`

`<ul>`  
  `{Object.entries(links).map(([platform, details]) => {`  
    `// Skip if the platform has no details or no URL provided`  
    `if (!details || !details.url) return null;`

    `return (`  
      `<li class="social-item">`  
        `<strong>{platform}:</strong>`   
        `<a href={details.url} target="_blank" rel="noopener noreferrer">`  
          `{details.title || platform}`  
        `</a>`  
        `{details.description && <p>{details.description}</p>}`  
      `</li>`  
    `);`  
  `})}`  
`</ul>`

## **Why "As-Is" is better here than a list:**

> * **Direct Access:** If you ever need to fetch *just* Instagram without looping through everything, you can type links.instagram.url instantly.  
> * **Cleaner YAML:** Your content creators don't have to worry about dash symbols (-) for lists.

If you want to fine-tune this, let me know:

> * Is this YAML file **the entire file** representing a single profile, or do you have **multiple items/profiles** in this file?  
> * Do you want to **strictly enforce** that url must always be present if a platform is listed?
```
